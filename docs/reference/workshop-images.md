# Workshop illustrations

## Curation

The inline image loader in `build_with_claude_workshop.html` uses `data-art` keys and tries `assets/workshop/<key>-01.jpg`, then `<key>-02.jpg`. Keep filenames unchanged; delete the unwanted option and reload. On Vercel, deploy the deletion first. No build step or directory listing is needed. Both missing or undecodable restores the text fallback. Copy the assets folder alongside the HTML for offline use.

- `harness`: visual interlude after the harness code walkthrough.
- `context-sources`: illustration replaces the six-way overview table visually; the table remains as fallback, and the following six slides hold the detail.
- `harness-location`: replaces the three location cards with a large infographic; distinguishes laptop sleep, hosted chat persistence and an always-on remote harness.
- `context-window`: explainer after “It only knows what is in the window”, followed by “Context rot”. Shows loaded inputs, attention, processing, next-token output and the append/repeat loop. Capacity is qualified by model; tokens are not words.
- `context-rot`: chart immediately after “One window in. One token out.” A conceptual decline, not benchmark data; no numeric thresholds. Original detailed explanation remains as fallback and in speaker notes.
- `skills-gym`: square gym satire alongside three practical pain → solution examples. Descriptions have overhead; full skill bodies load on trigger, rather than all installed skills loading in full.
- `context-map`: map/library metaphor for CLAUDE.md pointing to feature references, with history in git. Original three cards are the fallback.
- `development-loop`: analyze → improve → implement → review, with findings returning to the plan. Original detailed workflow is the fallback.
- `llm-wiki`: interconnected Markdown notes as an owned knowledge base, following the docs lifecycle.
- `reasoning-effort`: existing benchmark graphic accompanying the reasoning-effort discussion.
- `mcp-plug`: universal-connector metaphor replacing the MCP mechanism cards, with the server-directory link kept in the caption.
- `git-savepoints`: local committed snapshots, experiments and recovery; GitHub is a separate shared copy. The caption retains the optional GitHub 101 session.
- `product-pieces`: front / memory / worker architecture replacing the three deployment-provider cards. The preceding deployment checklist retains the broader operational pieces.
- `claude-levels`: visual interlude immediately after the global/project comparison. One global file supplies personal preferences across projects; each project adds its own map and usage instructions.
- `docs-lifecycle`: replaces the working-memory lifecycle cards. Durable knowledge goes into reference docs; the spent plan goes into the write-only archive, not the reference doc itself.
- `imagination-amplifier`: square illustration alongside the closing imagination/amplifier message. Copy remains visible if both variants are removed; mobile stacks copy and artwork.

For these last three slides, `.art-summary` is the short caption shown with loaded artwork; `.art-fallback` retains the original detail if both candidates fail. The loader deliberately probes two known JPEG filenames rather than requesting a directory listing, so it works on static hosts and `file://`. While both options exist, `01` wins. Reload after deletion; arbitrary renames are not discovered. Diagrams are contained, never cropped.

## Shared style

Wintercircus editorial diagram: graphite ground, warm cream geometry, circus-red emphasis, restrained ultramarine and magenta, crisp geometric type, subtle print grain, generous negative space.

Generated with the built-in image generation tool. JPEGs are approximately 16:9, except the square `skills-gym` and `imagination-amplifier` pairs. `object-fit: contain` preserves full diagrams; mobile uses natural image height and stacks the gym image above its examples. Deleted options need not be regenerated: curation is intentional.
